**核心方案采用“Playwright + Python 测试层 + 配置驱动 + Agent/Skill 封装”架构，通过环境变量与 Profile 实现单机/云端无缝切换，以 pytest 插件或独立 CLI 提供可迁移的端到端自动化测试能力。**

### 🔧 技术选型与理由
| 层级 | 选型 | 理由 |
|------|------|------|
| UI 驱动 | **Playwright** (`_electron` API) | 官方推荐，原生支持 Electron 启动/连接，Locator API 稳定 |
| 测试框架 | **pytest** (Python) | 与你的 Python 服务同语言，fixture 机制天然支持 setup/teardown |
| 配置管理 | **YAML profiles** + 环境变量 | 一套代码多环境切换，CI/CD 友好 |
| 云端运行 | **CDP 远程连接** / Xvfb headless | 无头环境可跑 Electron，或通过 CDP 连远程实例 |

### 🎯 Driver 层实现
**`drivers/electron_driver.py`**
```python
from playwright.async_api import async_playwright

class ElectronDriver:
    def __init__(self, config):
        self.config = config
        self.app = None
        self.page = None

    async def start(self):
        pw = await async_playwright().start()
        cfg = self.config["electron"]

        if cfg.get("connect_via") == "cdp":
            # 云端模式：连接远程 Electron
            browser = await pw.chromium.connect_over_cdp(cfg["cdp_url"])
            context = browser.contexts[0]
            self.page = [p for p in context.pages
                         if not p.url.startswith("devtools://")][0]
        else:
            # 本地模式：启动 Electron
            self.app = await pw._electron.launch(
                args=[cfg["app_path"], *cfg.get("args", [])],
                env={**os.environ, "NODE_ENV": "test"}
            )
            self.page = await self.app.first_window()

    async def stop(self):
        if self.app:
            await self.app.close()

    # 统一交互接口
    async def click(self, selector): ...
    async def fill(self, selector, text): ...
    async def wait_for(self, selector, timeout=None): ...
    async def screenshot(self, path): ...
```

### ☁️ 云端部署方案
| 方案 | 适用场景 | 实现方式 |
|------|---------|---------|
| **Xvfb + Electron** | 完整 E2E | Docker 中装 Xvfb，headless 跑 Electron |
| **CDP 远程连接** | 已有云端 Electron 实例 | `connect_over_cdp()` 直连 |
| **分离测试** | 后端逻辑为主 | API 层用 `httpx` 直测，UI 层单独跑 |

### 📌 关键决策点
- **为什么 Playwright 而非 Selenium/WDIO**：Playwright 的 `_electron` API 是官方推荐的 Electron 测试方式，支持 main process 和 renderer process 双向操作，且 Python 绑定成熟
- **为什么 Skill 模式**：每个业务场景封装为独立 Skill，可组合、可复用、可单独调试，新增测试场景只需新增一个 Skill 文件
- **为什么 YAML Profile**：零代码切换环境，CI/CD 只需设置 `E2E_PROFILE` 环境变量即可，迁移到新机器只需新增一个 profile 文件

该方案的核心优势在于**配置与代码分离**、**Skill 可插拔**、**单机/云端一套代码**。你可以先从 `local` profile 开始，跑通基本流程后，再逐步添加 `ci` 和 `cloud` profile。
